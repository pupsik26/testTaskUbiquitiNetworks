# Обработка заказов (CLI, PHP)

Скрипт `orders.php` читает заказы из JSON и выводит отчёт. Спецификация: `Specs/orders-processing.md`.

## Что реализовано

- количество и общая сумма оплаченных заказов (`status = paid`);
- самый дорогой оплаченный заказ (при равных суммах — первый по порядку);
- группировка заказов по статусам (`paid`, `pending`) с количеством, нулевые группы тоже выводятся;
- проверка каждой записи и сводка по пропущенным: все проблемы записи перечисляются сразу, дубли `id` пропускаются, суммы считаются в копейках без погрешности float.

## Требования

PHP 8.1+ **или** Docker. Зависимости и Composer не нужны.

## Запуск

Локально:

```bash
php orders.php
php orders.php data/bad_amount.json
```

Через Docker, без установленного PHP (из корня проекта, PowerShell):

```powershell
docker run --rm -v "${PWD}:/app" -w /app php:8.1-cli php orders.php data/bad_amount.json
```

В Git Bash добавьте префикс `MSYS_NO_PATHCONV=1`. Для PHP 8.3 замените тег на `php:8.3-cli`.

Файлы для проверки обработки ошибок лежат в `data/`:

```bash
php orders.php data/empty.json
php orders.php data/missing_field.json
php orders.php data/bad_amount.json
php orders.php data/unknown_status.json
php orders.php data/duplicate_id.json
php orders.php data/invalid_json.json
php orders.php data/not_list.json
```

Отчёт выводится в STDOUT, предупреждения и ошибки — в STDERR. Посмотреть только ошибки: `php orders.php data/bad_amount.json 1>$null` (PowerShell). Код выхода: `echo $LASTEXITCODE`.

## Обработка ошибок

| Ситуация | Поведение | Код |
|---|---|---|
| Всё корректно (в том числе `[]`) | Отчёт в STDOUT | 0 |
| Только предупреждения (округление) | Отчёт в STDOUT, предупреждения в STDERR | 0 |
| Часть записей пропущена | Отчёт по корректным записям, строка по каждой пропущенной в STDERR, сводка в отчёте | 2 |
| Файл не найден или не читается | `Ошибка: …` в STDERR | 1 |
| JSON не декодируется | `Ошибка: не удалось декодировать JSON: …` | 1 |
| Корень не список (объект, скаляр) | `Ошибка: ожидается JSON-массив заказов` | 1 |
| Непредвиденное исключение | `Ошибка: …` | 1 |

Запись пропускается, если: не объект, нет обязательного поля (`id`, `customer`, `amount`, `status`) или оно `null`, `id` не положительное целое, `customer` пустой, `amount` не число или отрицательный, статус не `paid`/`pending` (регистр важен), `id` повторяется.

## Допущения

- `amount` — число или строка, проходящая `is_numeric()` (`"1500.50"`, `" 2000 "`, `"1e3"`); строки вроде `"1500,50"` и `"abc"` отвергаются. `0` допустим.
- Суммы хранятся в копейках; если знаков после точки больше двух, сумма округляется с предупреждением.
- `id` — целое > 0 или строка из цифр (`"101"`). Дубликат: остаётся первое вхождение.
- Пустой объект `{}` — ошибка формата, а не пустой список.

Проверено: `php -l` и все прогоны дают одинаковый результат на локальном PHP 8.3.25 и в Docker `php:8.1-cli`, `php:8.3-cli`.
