# Обработка заказов (CLI, PHP)

Скрипт `orders.php` читает заказы из JSON и выводит: число и сумму оплаченных заказов, самый дорогой оплаченный заказ, группировку по статусам и сводку по пропущенным (некорректным) записям. Спецификация — `Specs/orders-processing.md`.

## Требования

PHP 8.1+ или Docker. Composer и внешние зависимости не нужны.

## Запуск

Локально:

```bash
php orders.php
php orders.php data/bad_amount.json
```

Через Docker (из корня проекта):

```powershell
docker run --rm -v "${PWD}:/app" -w /app php:8.1-cli php orders.php
```

В Git Bash добавьте префикс `MSYS_NO_PATHCONV=1`. Для PHP 8.3 замените тег на `php:8.3-cli`.

Файлы для демонстрации: `data/invalid_json.json`, `not_list.json`, `empty.json`, `missing_field.json`, `bad_amount.json`, `unknown_status.json`, `duplicate_id.json`. Пример: `php orders.php data/duplicate_id.json`.

Проверено: `php -l` и все прогоны дают одинаковый результат и коды выхода на локальном PHP 8.3.25 и в `php:8.1-cli` (8.1.34), `php:8.3-cli` (8.3.33). Различие только в переводе строки (на Windows `PHP_EOL` — `\r\n`).

## Обработка ошибок

| Ситуация | Поведение | Код |
|---|---|---|
| Всё корректно (в том числе `[]`) | Отчёт в STDOUT | 0 |
| Только предупреждения (округление) | Отчёт в STDOUT, предупреждения в STDERR | 0 |
| Часть записей пропущена | Отчёт по корректным записям, строка по каждой пропущенной в STDERR, сводка в отчёте | 2 |
| Файл не найден / не читается | `Ошибка: …` в STDERR | 1 |
| JSON не декодируется | `Ошибка: не удалось декодировать JSON: …` | 1 |
| Корень не список | `Ошибка: ожидается JSON-массив заказов` | 1 |
| Непредвиденное исключение | `Ошибка: …` | 1 |

Запись проверяется целиком: в сообщении перечислены все найденные проблемы. Некорректные записи не прерывают работу, а исключаются из расчётов.

## Допущения

- Известны только статусы `paid` и `pending`; сравнение строгое, с учётом регистра (`PAID` — неизвестный статус).
- `amount`: число или строка, проходящая `is_numeric()` (`"1500.50"`, `" 2000 "`, `"1e3"`). Мусорные строки не приводятся молча. `0` допустим.
- Суммы хранятся в копейках (`int`); перевод — `(int) round($amount * 100)`. Если знаков после точки больше двух, сумма округляется и выводится предупреждение.
- `id`: целое > 0 или строка из цифр (`"101"`).
- При равных суммах самым дорогим считается первый заказ по порядку.
- Дубликат `id`: остаётся первое вхождение, повтор пропускается. Проверяется только среди записей, прошедших остальную валидацию.
- «Распознанная сумма» в пропущенных записях — сумма тех, у которых поле `amount` корректно.
- Пустой объект `{}` считается ошибкой корня (не список), а не пустым списком.
- Код выхода 2 отличает частичный успех от полного отказа (1).
