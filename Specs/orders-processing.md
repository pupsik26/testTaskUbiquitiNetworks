# Спецификация: обработка заказов (CLI, PHP)

Статус: реализовано, проверено (см. Specs/decisions.md).

## 1. Цель и рамки

CLI-скрипт на PHP, который читает список заказов из JSON и выводит:

1. количество оплаченных заказов (`status = paid`);
2. общую сумму оплаченных заказов;
3. самый дорогой оплаченный заказ;
4. группировку заказов по статусам с количеством в каждой группе (Часть 3, вариант Б);
5. сводку по пропущенным (некорректным) записям.

Ожидаемый результат на исходных данных из задания: 3 заказа, сумма 4500, самый дорогой — № 103 на 3000.

**Вне рамок:** веб-интерфейс, Composer, PHPUnit и автотесты, Dockerfile и docker-compose, варианты А и В Части 3, CLI-флаги, кроме пути к файлу.

## 2. Окружение

- Минимальная версия — **PHP 8.1**. Код должен работать на 8.1 без изменений.
- Разрешено (есть в 8.1): `enum`, `readonly`-свойства, `match`, именованные аргументы, `never`, `array_is_list()`, first-class callable syntax.
- Запрещено, потому что этого нет в 8.1:
  - `readonly`-классы и DNF-типы (появились в 8.2);
  - типизированные константы классов и `json_validate()` (появились в 8.3).
- Проверка выполняется **двумя способами, обязательно оба**:
  1. локально — установленным PHP (`php orders.php`, у автора 8.3.25);
  2. через Docker — официальные образы `php:8.1-cli` (минимальная версия) и `php:8.3-cli`.
- Основной способ запуска — `php orders.php`. Docker — альтернатива для проверки на минимальной версии и для запуска без локального PHP. В README описаны оба способа.

## 4. Входные данные

- Путь к файлу: первый аргумент CLI (`$argv[1]`). Без аргумента — `__DIR__ . '/orders.json'`.
- Ожидаемый формат: JSON-массив (список) объектов с полями `id`, `customer`, `amount`, `status`. Лишние поля игнорируются.
- Декодирование: `json_decode($json, true, 512, JSON_THROW_ON_ERROR)`, `JsonException` перехватывается.
  - Источник: https://www.php.net/manual/ru/function.json-decode.php
- Проверка корня: результат должен быть массивом и `array_is_list()` (PHP 8.1+).
  - Источник: https://www.php.net/manual/ru/function.array-is-list.php

## 5. Модель

```php
enum OrderStatus: string
{
    case Paid = 'paid';
    case Pending = 'pending';
}

final class Order
{
    public function __construct(
        public readonly int $id,
        public readonly string $customer,
        public readonly int $amountCents,   // сумма в копейках
        public readonly OrderStatus $status,
    ) {}
}
```

- Известны **только** статусы `paid` и `pending`. Сравнение строгое, с учётом регистра, через `OrderStatus::tryFrom()`.
  - Источник: https://www.php.net/manual/ru/backedenum.tryfrom.php
- Суммы хранятся в копейках (`int`), чтобы при суммировании не было погрешности float.

## 6. Функции

Все функции, кроме `main`, — чистые: без вывода и без `exit`.

| Функция | Назначение |
|---|---|
| `readOrdersFile(string $path): string` | Прочитать файл. Нет файла или не читается → `RuntimeException` (фатально). |
| `decodeOrders(string $json): array` | Декодировать JSON и проверить, что корень — список. Иначе исключение (фатально). |
| `validateOrder(mixed $raw): Order` | Проверить и нормализовать одну запись. При ошибке — `InvalidOrderException` со **всеми** найденными проблемами записи. |
| `parseOrders(array $rawList): array` | Прогнать все записи, отсеять дубли `id`. Возвращает `['orders' => list<Order>, 'skipped' => list<SkippedRecord>, 'warnings' => list<string>]`. |
| `filterPaid(array $orders): array` | Заказы со статусом `paid`. |
| `sumAmount(array $orders): int` | Сумма в копейках. |
| `findMostExpensive(array $orders): ?Order` | Максимум по сумме. При равенстве — **первый** по порядку (сравнение строго `>`). Пустой список → `null`. |
| `groupByStatus(array $orders): array` | `['paid' => n, 'pending' => m]`. Все известные статусы присутствуют, в том числе с 0. |
| `formatMoney(int $cents): string` | Целая сумма → `4500`, дробная → `1500.50`. |
| `main(array $argv): int` | Связка, вывод, код выхода. |

Количество оплаченных считается через `count(filterPaid(...))`.

`SkippedRecord` хранит: позицию записи (с 1), `id`, если удалось прочитать, список причин и распознанную сумму в копейках (или `null`).

## 7. Правила валидации записи

Запись проверяется целиком: выводятся все проблемы, а не только первая.

| Поле / ситуация | Принимается | Ошибка → запись пропускается |
|---|---|---|
| Запись в целом | ассоциативный массив (JSON-объект) | не массив (число, строка, `null`) → «запись не является объектом» |
| Наличие полей | `array_key_exists` для `id`, `customer`, `amount`, `status` | «отсутствует обязательное поле `X`» |
| Значение `null` | — | «поле `X` равно null» (отдельно от «отсутствует») |
| `id` | `int > 0`; строка из цифр (`"101"`, с пробелами по краям) → `int` | float, bool, массив, нецифровая строка, `≤ 0` |
| `customer` | строка, непустая после `trim` | не строка, пустая строка |
| `amount` | `int`, `float`; строка, проходящая `is_numeric()` (`"1500"`, `"1500.50"`, `" 1500 "`, `"1e3"`) | bool, массив, строка не по `is_numeric` (`"1500,50"`, `"1 500"`, `"1500 руб."`, `"abc"`), отрицательная, `INF`/`NAN` (например, `"1e999"`), переполнение при переводе в копейки |
| `status` | строка, точно `paid` или `pending` | не строка; неизвестное значение («неизвестный статус `cancelled`») |
| Дубль `id` | первое вхождение | повтор → «дубликат номера заказа 101 (первое вхождение — запись 1)» |

Дополнительно:

- `amount = 0` — корректно (в задании заказ 104 с суммой 0 учитывается как оплаченный).
- Перевод в копейки: `(int) round($amount * 100)`. Если знаков после точки больше двух (`10.005`), сумма округляется, и выводится **предупреждение**. Запись не пропускается.
- `is_numeric()` в PHP 8 допускает пробелы в начале и в конце строки.
  - Источники: https://www.php.net/manual/ru/function.is-numeric.php, https://wiki.php.net/rfc/saner-string-to-number
- Приведение `(float)` и `(int)` к «мусорным» строкам **не используется**: оно молча даёт 0 или частичное число.
- Дубли проверяются только среди записей, прошедших остальную валидацию.

## 8. Обработка ошибок и коды выхода

| Ситуация | Поведение | Код |
|---|---|---|
| Всё корректно (в том числе пустой список `[]`) | Отчёт в STDOUT | `0` |
| Есть только предупреждения (округление) | Отчёт в STDOUT, предупреждения в STDERR | `0` |
| Часть записей пропущена | Отчёт по корректным записям в STDOUT; по каждой пропущенной — строка в STDERR; сводка о пропущенных — в отчёте | `2` |
| Файл не найден или не читается | `Ошибка: …` в STDERR, отчёта нет | `1` |
| JSON не декодируется | `Ошибка: не удалось декодировать JSON: <сообщение JsonException>` в STDERR | `1` |
| Корень не список (объект, скаляр) | `Ошибка: ожидается JSON-массив заказов` в STDERR | `1` |
| Непредвиденное исключение | `Ошибка: …` в STDERR | `1` |

Строка о пропущенной записи (STDERR):

```
Пропущена запись 3 (id 103): сумма отрицательная (-100)
Пропущена запись 5 (id —): отсутствует обязательное поле "id"; неизвестный статус "PAID"
```

## 9. Формат вывода (STDOUT)

Корректные данные (`orders.json`):

```
Количество оплаченных заказов: 3
Общая сумма оплаченных заказов: 4500
Самый дорогой оплаченный заказ: № 103 на сумму 3000

Заказы по статусам:
  paid: 3
  pending: 1

Пропущено записей: 0
```

Есть пропущенные записи:

```
Пропущено записей: 2 (распознанная сумма в них: 1200; подробности — в STDERR)
```

Нет оплаченных заказов:

```
Количество оплаченных заказов: 0
Общая сумма оплаченных заказов: 0
Самый дорогой оплаченный заказ: оплаченных заказов нет
```

- Группировка учитывает только корректные записи. Пропущенные в группы не попадают, они идут отдельной строкой.
- Формат сумм — по `formatMoney`: целые без дробной части, дробные с двумя знаками через точку.

## 10. Запуск

Локально:

```bash
php orders.php
php orders.php data/bad_amount.json
```

Через Docker (из корня проекта, альтернативный способ):

```bash
docker run --rm -v "${PWD}:/app" -w /app php:8.1-cli php orders.php
```

- PowerShell понимает `${PWD}`.
- В Git Bash нужен префикс `MSYS_NO_PATHCONV=1`, иначе `/app` превратится в Windows-путь.
- Для проверки на 8.3 тег меняется на `php:8.3-cli`.
  - Образы: https://hub.docker.com/_/php
